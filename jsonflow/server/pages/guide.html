How to use jsonflow

An agent is a flow of steps on a canvas. Steps are tools from your MCP servers, LLM calls, transforms and routers. You connect them, set their values, run the agent, and publish it so other systems can call it as an MCP tool. This guide builds up from an empty agent to a published one.

Want to see a finished agent first? Open Sector event discovery in the Credit Risk category. It searches news, groups articles into events, ranks them and checks them against trusted sources.

1. Roles and signing in

There are two roles. A super admin creates every account; there is no self sign-up.

TaskAdminSuper admin
Build, edit, validate and run agentsYesYes
Publish and unpublish agentsYesYes
See every run and its audit filesYesYes
Delete agentsNoYes
Manage users, categories, MCP servers and the modelNoYes
Issue and revoke MCP API keys, read the audit logNoYes

Sign in with your username and password. Five wrong attempts lock the account for five minutes. Change your password from the Password button in the top bar; you will be signed out everywhere.

2. The agents page

After signing in you land on Agents. Agents are grouped by category. Each card shows whether it is published, its version, and how its last run went. The right column lists recent runs from every trigger: the app, MCP clients and other agents. It also shows the MCP addresses for your agents.

3. Create an agent

  1. Select New agent.
  2. Give it a name. The name becomes its id, for example Limit Watch becomes limit_watch. The id is also its MCP tool name and never changes.
  3. Pick a category. Categories group agents in the app and on MCP. Only a super admin can add categories.
  4. Start blank, copy an existing agent, or paste agent JSON exported from another installation.

The builder opens with a single start step. Keep it, replace it, or delete it once you have added others.

4. Add and connect steps

The builder has three areas: the palette on the left, the canvas in the middle and the inspector on the right.

  • Add a step: drag an item from the palette onto the canvas, or click it to drop it near the middle. The palette search filters by name and description.
  • Move a step: drag its card.
  • Connect: drag from the small circle on a card's right edge onto another card. A step with no outgoing connection ends the agent.
  • Parallel branches: connect one step to several. They run at the same time.
  • Select: click a card or a connection. Press Delete, or use the inspector's delete button, to remove it.
  • Start: the step marked start runs first. Change it from the step's inspector.
  • Pan and zoom: scroll, drag the empty canvas, or use the zoom buttons. Fit brings every step into view; Tidy lays the flow out left to right.

5. Set values three ways

Every value a step needs offers three modes. Pick per field.

ModeUse it forExample
Fixed valueA constant5, reuters.com, sec.gov
Pick from dataAn agent input or another step's output, from a listinputs.country, nodes.collect_articles
ExpressionAnything more: a field deep inside a result, text with values mixed in, or a filter{{ event.validation_query | truncate(300) }}

Expressions

An expression sits inside {{ }}. A field that is exactly one expression keeps the value's type, so a list stays a list. Text with expressions mixed in becomes text.

  • inputs.<name> is an agent input. nodes.<step id> is a step's output. run.date and run.id describe the run.
  • Reach inside with dots and indexes: nodes.search.results[0].title.
  • Inside a repeated step, item (or the name you chose) is the current item and index its position.

default(x)Use x when the value is missing. Add it to anything that might not exist, such as output of a branch that did not run.

6. Tool steps

Tool steps call a tool on a connected MCP server. The palette groups tools as web, structured data, unstructured documents, agents and other.

  • The inspector lists the tool's arguments from its schema. Required ones are marked.
  • Values are checked against the schema before the call, so a wrong type fails fast with a clear message instead of a confusing server error.
  • Keep from result takes one field of the result, for example results, so later steps get just the list.
  • Retries repeats a failed call up to three times. Timeout caps a slow call.

7. LLM steps

  • Write the prompt in the inspector. Use the insert buttons under the prompt to add inputs and earlier outputs; they insert expressions such as {{ nodes.collect_articles | pretty }}.
  • Add an optional system prompt for standing rules, such as "work only from the supplied articles".
  • Structured output takes a JSON Schema whose top level is an object. The answer is checked against it. If it does not match, the model gets one automatic correction; if it still fails, the step fails. Later steps can then rely on fields like nodes.extract_events.events.
  • Leave provider and model blank to use the model a super admin configured. Set them only when a step needs a different one.
Ask for references, not URLs. In the example agent the model cites articles by number and a transform attaches the real URLs. That stops invented links.

8. Transform steps

A transform takes one input value and applies steps in order. No model and no tool are involved, so transforms are free and predictable.

StepDoes
flattenTurn a list of lists into one list, optionally taking a list field from each item first, such as results
filterKeep items where a condition holds
dedupeKeep the first item per key; normalize URLs or text so near-duplicates match
sortSort by one or more keys; a rank map orders words such as high, medium, low
limitKeep the first n items

pickKeep only listed fields
lookupJoin: attach matching items from another list, like a spreadsheet lookup
renderReplace the value with a template built from it

9. Routers

A router checks its routes top to bottom and follows the first that matches; otherwise it follows else. Each route has a left value, a comparison and a right value, for example {{ nodes.collect_articles | length }} greater than 0. Each route has its own circle on the card's right edge; drag from it to the step that should follow. An unconnected route ends the agent.

10. Repeat and run in parallel

  • Repeat for each item: switch it on in any tool, LLM or transform step. Choose the list, a name for the current item, the most items to process, and Concurrency, how many run at once. The step's output is a list of results in the same order.
  • If one item fails the others continue by default, and the failed item's result is empty. Set On item error to stop instead.
  • Parallel branches: connect one step to several. Where branches meet, set When several branches lead here to Wait for all so the step runs once with every branch's output. Leave it on Run per branch when a router chose between the branches.
  • Every call in every branch counts against the agent's budget, so parallel work cannot overspend.

11. Inputs, output and budgets

Click empty canvas to open the agent's settings.

  • Inputs are the values a run starts with, such as country and sector. Each has a type, an optional default and a description. They become the arguments of the agent's MCP tool.
  • Output is what a run returns and what MCP callers receive. Pick one step's output, or write a JSON template that combines several.
  • Budgets cap tool calls, LLM calls and total steps per run. A run that hits a cap stops that work and reports it.

12. Validate, save and versions

  • Validate checks the whole agent against the live tool list: missing steps, unknown tools, missing required arguments, references to steps that do not exist, and steps that can never run. Click a problem to jump to its step.
  • Save (or Ctrl+S) stores a new version even with problems, so you never lose work. Published agents that are saved with errors are unpublished automatically.
  • If a colleague saved while you were editing, you are told and nothing is overwritten. Reload to see their version.
  • Versions in the agent settings lists every save with who and when. Every run records the version it used.

13. Run and read the results

  1. Select Run. Fill in or keep the input values and confirm.
  2. The run page shows each step as it runs, finishes, fails or is skipped, with the path taken highlighted.
  3. The left panel is the trace in execution order with durations. Click a step to see its output and every tool and LLM call it made, including the exact prompt sent.
  4. The right panel shows the run's output, inputs, call counts against budget, and any error.

14. Publish as an MCP tool

Select Publish in the builder. The agent must pass validation first. Published agents are tools on this product's MCP endpoint:

All published agents         POST https://<host>/mcp
One category only            POST https://<host>/mcp/category/<category-slug>
Authentication               Authorization: Bearer <API key>
  • The tool name is the agent id. The description starts with the category in brackets. The arguments are the agent's inputs.
  • The result is the agent's output as JSON. Each call is recorded as a run with trigger mcp and the key's name.
  • A super admin issues API keys and can limit a key to some categories.

Connect a client

Any MCP client that speaks Streamable HTTP can connect. For a SAJHA-style registry or this product's own server list, add:

"credit_risk_agents": {
  "transport": "mcp_http",
  "url": "https://<host>/mcp/category/credit-risk",
  "headers": {"Authorization": "Bearer ${JSONFLOW_API_KEY}"}
}

15. Agents that call agents

Published agents also appear in the palette under agents, so one agent can use another as a step. An agent cannot call itself or an agent already in its chain, and chains stop at three levels. The inner agent's run is recorded separately with trigger agent.

16. Super admin tasks

Open Admin in the top bar.

  • Users: create admins and super admins, change roles, disable accounts and reset passwords. Disabling or changing a role signs the person out. At least one active super admin always remains, and you cannot demote or disable yourself.
  • Categories: add categories, or delete one that no agent uses.
  • MCP servers: edit the server list. Each server has a transport (sajha_rest for SAJHA, mcp_http for any standard MCP server), an address, authentication by environment variable, and allow and deny lists of tool name patterns. Test lists a server's tools live. Keep write tools such as *_send_* and *_delete_* on the deny list.
  • Model: choose Anthropic or any OpenAI-compatible endpoint, the default model, and the name of the environment variable that holds the key. Keys are never typed into the app. Test sends a one-line prompt.
  • API keys: create a key for each MCP client, optionally limited to categories. The key is shown once. Revoke keys that are no longer used.
  • Audit log: sign-ins, saves, publishes, settings changes, user changes and key changes, newest first.

First start

python -m jsonflow.server create-user --username you --role super_admin
python -m jsonflow.server serve --host 0.0.0.0 --port 8080

Add --demo to serve to explore with synthetic search results and scripted model answers, without network access or keys.

17. Troubleshooting

MessageWhat to do
references unknown node 'nodes.x'A value points at a step that was renamed or deleted. Pick the value again.
'nodes.x' is not availableThat step did not run on this path, often because a router skipped it. Add | default(...) or connect the steps differently.
missing required tool argsFill in the arguments marked required.
arguments do not match the tool schemaA value has the wrong type or range. The message names the field.
tool ... is blocked by the server allowlistA super admin has hidden that tool. Ask them if it should be allowed.
budget ... reachedRaise the budget in agent settings, or reduce items in repeated steps.
output failed schema validationThe model's answer did not fit the output schema twice. Simplify the schema or make the prompt more explicit.
N branches lead hereSeveral branches meet at a step. Choose Wait for all if they run in parallel.
unreachable from the start nodeConnect the step, or delete it.
