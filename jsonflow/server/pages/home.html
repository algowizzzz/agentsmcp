How it works

An agent is a flow of steps you can see. The flow decides the order; models only work inside the steps you give them.

1

Connect your tools

A super admin registers MCP servers once. Their tools appear in the palette, grouped as web, structured data and documents. Write tools such as send or delete stay hidden.

2

Draw the agent

Drag tools and LLM steps onto the canvas and connect them. Each tool's settings form comes from its own schema. Values are fixed, picked from earlier steps, or written as expressions.

3

Run and publish

Validate, run, and inspect every step's input and output. Publish the agent and it becomes an MCP tool in its category, ready for other agents and systems.

Building blocks

Five kinds of step cover most work.

Tool

Any tool from a connected MCP server: news and web search, SQL, documents, filings. Arguments are checked against the tool's schema before every call.

LLM call

A prompt with data from earlier steps. Give it an output schema and the answer comes back as checked JSON, with one automatic correction if it is off.

Transform

Flatten, filter, dedupe, sort, limit, join and reshape data without code or tokens.

Router

Branch on a condition, for example skip the LLM when a search returned nothing.

Repeat and parallel

Run any step once per item of a list, many at a time. Split the flow into branches that run side by side and join again.

Other agents

Published agents appear in the palette too, so one agent can call another. Loops between agents are refused.

Every agent is an MCP tool

Publishing an agent adds it to this product's MCP endpoint. Each agent belongs to one category, and each category also has its own endpoint, so a client can see only, say, Credit Risk agents. API keys are issued by a super admin and can be limited to categories.

POST /mcp                       all published agents
POST /mcp/category/credit-risk  one category only
Authorization: Bearer jfk_…

Built for controlled environments

  • Two roles: admins build and run agents; super admins also manage users, categories, servers, the model and API keys.
  • Budgets cap tool calls, LLM calls and steps on every run.
  • Each run stores the exact agent version, every prompt, every tool call and every step's output.
  • Each save creates a version; the audit log records who changed what.
  • Works with Anthropic or any OpenAI-compatible model endpoint.
